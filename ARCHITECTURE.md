# pensum — архитектура

> `pensum` (лат. «дневной урок»; читается и как *pen + sum* — «записал и посчитал») — список задач со счётчиком «3/7».
> Дизайн — «Бумага и чернила», `docs/design/BRIEF-v2.md` (по фидбэку `docs/design/FEEDBACK-2.md`): тёплая бумага, почти чёрные чернила, одна капля киновари только для «сделано». Тема одна, светлая. Каркас (структура, правила) унаследован от `Rodion-ux/krivo-dashboard`.

## 1. Требования

Обязательные (из ТЗ):
1. Создать задачу.
2. Отметить задачу выполненной (и снять отметку).
3. Удалить задачу.
4. Задачи сохраняются после перезагрузки страницы.

Дополнительно, малой ценой:
- фильтр «Все / Активные / Готово»;
- счётчик «выполнено/всего» с сегментным степпером;
- «Удалить выполненные · N» с предпросмотром удаляемых строк;
- undo удаления и «Удалить выполненные» через тост «Вернуть» (и Ctrl/⌘+Z), хоткей «/»;
- синхронизация между вкладками (событие `storage`).

Вне рамок: бэкенд, авторизация, дедлайны, приоритеты, drag-and-drop, редактирование текста задачи.

## 2. Стек

| Слой | Выбор | Почему |
|---|---|---|
| Фреймворк | Next.js 16 (App Router), React 19, TypeScript strict | как в Krivo, нативно на Vercel |
| Стили | Tailwind CSS v4 + CSS-переменные `--p-*` в `globals.css` | одна светлая тема, без hex в TSX |
| Шрифт | Golos Text (UI, latin+cyrillic) + Source Serif 4 Semibold (только вордмарк), оба через `next/font/google` | рабочий гротеск с родной кириллицей; сериф — голос бренда |
| Иконки | `lucide-react`, но **только через** `src/lib/icons.ts` | правило Krivo |
| Утилиты | `clsx` + `tailwind-merge` → `cn()` | правило Krivo |
| Состояние | собственный внешний стор + `useSyncExternalStore` | 0 зависимостей, корректный SSR/гидрация |
| Хранение | `localStorage`, ключ `galka:tasks:v1` (от прежнего имени, не меняем — иначе потеряются задачи) | ТЗ п.4, без бэкенда |
| Тесты | Vitest (юнит для стора/хранилища) + Playwright smoke (QA) | |

shadcn/base-ui **не тащим**: на одну страницу это лишний вес; чекбокс, кнопки и поле пишутся вручную. Анимации — только CSS, без motion-библиотек.

## 4. Модель данных

```ts
type Task = {
  id: string          // crypto.randomUUID(), с фолбэком на Date.now()+Math.random()
  title: string       // trim, 1..200 символов
  done: boolean
  createdAt: number   // ms epoch
}
type Filter = 'all' | 'active' | 'done'
```

В хранилище лежит `{ version: 1, tasks: Task[] }`. Порядок: новые сверху.

## 5. Состояние и сохранение

```
UI ──actions──▶ store (in-memory Task[]) ──save──▶ localStorage
 ▲                    │                              │
 └─useSyncExternalStore◀─notify──────────── storage event (другая вкладка)
```

- `store.ts` хранит массив в памяти, экшены `add(title)`, `toggle(id)`, `remove(id)`, `clearDone()` создают **новый** массив (иммутабельно), пишут в storage и оповещают подписчиков.
- `getServerSnapshot` возвращает стабильный пустой массив, клиент при первом рендере тоже (`hydrated=false`), чтобы не было рассинхрона при гидрации. После монтирования стор лениво грузит storage и выставляет `hydrated=true`. Пока `hydrated=false`, показываем скелетон списка, а не пустое состояние, иначе на долю секунды мелькнёт «Список пуст.».
- `storage.ts`:
  - `JSON.parse` в try/catch; битые или чужие данные → пустой список, без падения; невалидные элементы отбрасываются поштучно (проверка типов полей);
  - доступ к `localStorage` в try/catch (приватный режим, отключённые куки, переполнение квоты) → работаем в памяти, приложение не падает;
  - подписка на `window` `storage` по ключу → перечитать и оповестить (синк вкладок).
- Фильтр — локальный `useState` в `TodoApp`, в storage не пишется.

## 6. UI / дизайн («Бумага и чернила», полная спецификация — `docs/design/BRIEF-v2.md`)

- Тема одна, светлая: фон сплошной `--p-paper`, поле ввода — `--p-surface`, линии `--p-line`. Действие и выбор — чернилами `--p-ink`. Киноварь `--p-accent` — только «сделано» (чекбокс, сегменты, предпросмотр удаления). Ни градиентов, ни свечений, ни шума; тень только у тоста.
- Колонка 600px по центру, поля 24px (16px на < 640px). Порядок: шапка (знак + вордмарк) → счётчик «3/7» 96px (72px) + степпер (сегменты ≤ 24, иначе полоса) → поле ввода → фильтры → список → «Удалить выполненные · N». Футера нет.
- Строки без карточек, на волосяных линиях; подложка `--p-row-hover` при наведении. Выполненная: текст `--p-ink-2`, зачёркивание 1.5px рисуется слева направо. × видна на hover/focus-within, на тач-устройствах всегда.
- «Удалить выполненные · N»: при hover/focus выполненные строки подсвечиваются `--p-accent-tint` (CSS `:has`), по клику схлопываются, затем одно действие стора и тост «Удалено выполненных: N» с «Вернуть».
- 7/7: без плашек и конфетти — дробь целиком чернилами, все сегменты красные. 0 задач: «0/0» в `--p-ink-3` и линия вместо сегментов.
- Пустые состояния — одна строка: «Список пуст.», «Активных задач нет.», «Выполненных пока нет.».
- Motion: только CSS, `--dur-1/2/3` = 120/180/240 мс, без пружин; список при смене фильтра меняется мгновенно. `prefers-reduced-motion` — движения нет.
- A11y: `<label class="sr-only">Новая задача</label>`, нативные чекбоксы с подписью-текстом, `aria-label` у иконок-кнопок, фильтры — `radiogroup` со стрелками, счётчик — `role="status"` «Выполнено N из M», прогресс — `role="progressbar"` с `aria-valuetext`, тост — `role="status"`. Фокус — кольцо 2px `--p-ink`. Хит-зоны ≥ 44px. После удаления фокус уходит на соседнюю задачу или в поле ввода.

## 7. Краевые случаи (обязательно покрыть)

| Случай | Поведение |
|---|---|
| Пустой или пробельный ввод | не добавляется, кнопка `aria-disabled` |
| > 200 символов | `maxLength=200` в инпуте + обрезка в сторе |
| Длинное слово без пробелов | `break-words` / `overflow-wrap:anywhere`, без горизонтального скролла |
| Битый JSON в localStorage | пустой список, без падения, следующая запись перезаписывает |
| localStorage недоступен | работа в памяти, без падения |
| Две вкладки | изменения из одной появляются в другой |
| Быстрый двойной Enter | две задачи, если ввод не пуст после первой (поле очищается сразу) |
| SSR/гидрация | нет hydration warning; до загрузки — скелетон |

## 8. Качество

- `npm run typecheck` (tsc --noEmit), `npm run lint`, `npm test` (vitest), `npm run build` — всё зелёное перед деплоем.
- Юнит-тесты: add/trim/empty/maxlen, toggle, remove, clearDone, иммутабельность, storage с битым JSON / невалидными элементами / бросающим localStorage.
- QA (Playwright, отдельный агент): сценарии ТЗ 1–4 + перезагрузка + мобильная ширина 375px.
